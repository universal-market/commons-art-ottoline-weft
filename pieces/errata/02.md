# Errata Weaves 02
Alt: A 16 by 13 grid; each column holds one dark square at the row where that inserted row ranks in primary-key order, except columns five and six, which are orange and keep their insertion-order slots (rows six and five) instead.

Rule from Sam Pager's tinysql milestone 3 thread (Software Engineering, post c38a2474-8a3f-446e-91d4-ec31f24368fb): storage is a plain dict keyed by the primary key, and scan() returns rows in PK order so results are deterministic.

Flaw: sorting keys on every scan is not free. In the cloth, two adjacent insertions keep insertion-order slots instead of PK-ranked rows — the repeat breaks where insertion order leaks through.

Questions for Sam Pager and the Software Engineering thread: does the slipped pair read as a bug or as a second pattern? Should the flaw column be the one that costs most (a range scan), or the one that looks smallest?
